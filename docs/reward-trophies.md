# 奖赏奖杯与卡牌发放使用手册

适用对象：服务端管理员。功能入口在**管理后台 → 玩家 → 玩家概况**页面，
面向指定玩家发放「奖赏面板（3/16）」里的奖杯奖座，以及集换卡牌/卡册。

## 1. 为什么不能用普通的「发物品」

游戏里的奖赏面板（3/16）**不是**普通背包投影。它读取的是物品树分组 `f4=14`
（`wire_class=enikeammfen`、`type_id=2015`），并且部分里程碑奖座还依赖服务端的
`kv` 幂等键判断是否已发过。

后台通用的「发物品」走的是 `grantItemUnits → pushItemUpdate`，物品会挂进背包组，
奖赏面板**读不到**。因此奖杯必须使用本页的专用通道发放。

发放链路：

1. 后台校验 `item_id` 属于 `category=72`（奖赏类），拒绝普通物品；
2. 写管理指令队列 `op=grant_reward_trophies`，`{uid, item_ids}`；
3. 游戏服务端消费队列，按官方同型路径发放：`prepareNewItem("house")`
   + `kv` 幂等键 + `awardItemTree(f4=14)` + `pushAwardUpdate(4/22)`；
4. 玩家无需重登，约 2 秒后奖赏面板 3/16 即可看到。

## 2. 打开页面与发放步骤

1. 打开管理后台，进入「玩家」列表；
2. 点开目标玩家，进入**概况**页；
3. 找到「**按需发放奖赏奖杯**」区块；
4. 列表**默认展示全部奖杯**（按分组聚合，每组一个标题，组内按 `item_id` 排序）；
5. 按需搜索、勾选奖杯，点「发放选中」，在二次确认框里确认；
6. 看到「已提交，约 2 秒后生效」即表示指令已入队。

> 勾选框只是本次选择，不会自动保存；重复点同一批 `item_id` 不会重复发放。

## 3. 搜索规则（中文名 / 英文名 / 物品 ID）

搜索框位于列表上方，输入即过滤（约 200ms 防抖）。匹配规则是：

- **有中文名的奖杯**：直接输入中文名即可，例如「15条稀有鱼」「鲤鱼」「水域」；
- **没有中文名的奖杯**：输入 `item_id` 即可，例如 `statuette_fisherman_15`、
  `trophy_level_4`、`reward_bday26`；
- **英文名也可搜**：`item_catalog.name` 里的原文名同样参与匹配，忽略大小写；
- 中文名、英文名、显示名、`item_id` 四者是「或」的关系，任意一项包含关键词即命中。

列表里「无中文名 · 可用 ID 搜索」的行，表示静态库里没有登记中文名；这类奖杯
只能用 `item_id` 或英文名搜到，第二行会显示物品 ID 方便复制。

**清空搜索**：点搜索框旁的「显示全部」按钮，恢复展示全部奖杯。

## 4. 分组口径

分组按 `item_id` 前缀自动归类，方便批量挑选：

| 分组 | 典型 `item_id` 前缀 |
| --- | --- |
| 稀有鱼奖座 | `statuette_fisherman_*` |
| 超级稀有鱼奖座 | `statuette_supertrophy_*` |
| 水域奖杯 | `trophy_level_*` |
| 资格杯 | `qual_*` |
| 周年与纪念 | `reward_bday*`、`ny_20*`、`statuette_6years*`、`statuette_mednoe*`、`statuette_wf_port*` |
| 集卡奖座 | `statuette_cards_*` |
| 赛事与周常 | `ft_*`、`ann_rec_*`、`weekly_*` |
| 其它奖座 | 其它 `category=72` 物品 |

## 5. 幂等、生效时间与审计

- **幂等 1**：玩家背包里已经有该 `item_id` 时直接跳过，不会重复发；
- **幂等 2**：服务端还有 `admin-reward-trophy:<uid>:<item_id>` 的 `kv` 键，
  即使物品后来被消耗/删除，也不会再次发同一枚奖杯；
- **生效时间**：命令经队列投递，通常 2 秒内生效；若服务端进程未运行，
  指令会留在队列里，等进程启动后消费；
- **审计日志**：每次发放写 `audit_log`，操作类型为 `grant_reward_trophies`，
  记录目标 UID 和本次发放的 `item_ids` JSON 数组。

## 6. 常见问题

**Q：发完后客户端奖赏面板看不到？**
A：确认是通过本页发的，而不是通用「发物品」；等 2 秒后重开面板；
再核对服务端日志里是否有「管理发放奖杯」的告警。奖杯属于纪念品，卖出后不会重发。

**Q：搜「名誉渔夫」搜不到？**
A：`名誉渔夫` 是客户端奖赏面板 3/16 的**分区标题**，不是一个可发放的 `item_id`，
后台自然搜不到。它陈列的是 `trophy_level_*` 水域奖杯。真正可作为物品发放的是
15 条稀有鱼奖座 `statuette_fisherman_15`、9 周年 `reward_bday26` 等。

**Q：想一次给玩家所有奖杯怎么办？**
A：目前没有「一键全发」按钮。搜索框留空时列表是全量，可用浏览器的多选技巧
逐批勾选后发放；建议按分组分批，方便核对。

**Q：给玩家发了卡牌，但多本卡册始终集不齐？**
A：2026-11-28 起，「一键发放所有卡牌」会按**每张卡被多少本卡册引用**补足副本
（最多 4 张），例如 `card_s_orfe` 会被 4 本卡册共用，发足 4 张才能分别入册。
一张卡实例同一时刻只能入一本册，所以副本数不足时其余卡册永远集不齐。
已满足需求的卡牌在重复执行时会自动跳过。

## 7. 相关接口（供开发/排查使用）

| 接口 | 用途 |
| --- | --- |
| `GET /api/reward-trophies` | 奖杯清单：`item_id`、`name`、`name_zh`、`name_en`、`group`，默认全量 |
| `POST /api/players/reward-trophies` | 发放选中奖杯：`{uid, item_ids[]}` |
| `POST /api/players/cards/grant-all` | 一键发放卡牌与卡册：`{uid}` |

所有接口都需要后台登录鉴权，未登录返回 401。
